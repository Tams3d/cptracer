# Contributing

Thanks for improving cptracer. This project is a static Astro site, so every change must work without a server, a database, or a client-side router.

## Setup

1. Install Bun 1.4 or Node.js 22.23.4 or newer.
2. Run `bun install`.
3. Run `bun run dev` and open the printed local URL.

No environment variables are required.

## Checks

Run these checks before opening a pull request.

| Command             | Purpose                               |
| ------------------- | ------------------------------------- |
| `bun run fmt:check` | Verify formatting with Oxfmt          |
| `bun run lint`      | Lint TypeScript and TSX with Oxlint   |
| `bun run check`     | Type-check Astro, TypeScript, and TSX |
| `bun run build`     | Type-check, then build to `dist/`     |

Apply formatting with `bun run fmt`. Oxlint does not parse `.astro` files; `astro check` covers them.

## Conventions

- Use Astro patterns. Pages and the app shell stay server-rendered; only interactive islands hydrate with `client:load` or `client:visible`.
- Use React 19 conventions: named imports, no `React.*` namespace, no wildcard imports, and `useSyncExternalStore` for external state.
- Keep user-facing copy in English (India). Write plain ASCII: no smart quotes, dashes, or other non-ASCII characters.
- Use `//` comments. CSS block comments are the only exception.
- Never edit files in `src/components/ui`. They are generated by shadcn. Pass appearance overrides through `className` at the usage site, or reinstall the primitive:

  ```bash
  bunx shadcn@latest add button card input label table --overwrite --yes
  ```

- Cache platform results in `localStorage` so reloads and route changes do not call the public APIs again. Only the refresh action bypasses the cache.
- Support light and dark themes, reduced motion, keyboard focus, and the collapsible sidebar in every change.
- Keep the dependency list compatible with the MIT licence. Do not add AGPL or GPL packages.

## Data flow

Handles and cached results live in `localStorage` under `platform-profile-handles` and `platform-profile-results`. Requests go directly from the browser to the Codeforces, AtCoder, and LeetCode public APIs. Do not add a proxy or analytics service.

## Pull requests

- Keep each pull request focused on one problem.
- Describe the behaviour before and after the change.
- Include a screenshot for visual changes in both themes.
- Confirm the checks above pass.

## Release

Merges to `main` deploy automatically on Vercel. The production origin is read from the build environment, so canonical URLs, Open Graph tags, and the sitemap stay correct without any project setting.
